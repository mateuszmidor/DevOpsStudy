## Context

The repository has no root README. The Grafana instance is deployed via the Grafana Operator in the `monitoring` namespace, with auto-generated admin credentials stored in a Kubernetes Secret. Access is via `kubectl port-forward` since the service defaults to ClusterIP with no Ingress.

## Goals / Non-Goals

**Goals:**
- Add a root `README.md` that documents deployment prerequisites, bootstrap steps, Grafana access instructions, and credentials retrieval
- Cover the two-step deployment flow: `make` (Helm bootstrap) → `make obs` (CRD apply)

**Non-Goals:**
- Creating ingress, LoadBalancer, or any external-facing URL for Grafana
- Documenting dashboard design, alert rules, or Prometheus internals
- Adding screenshots or visual content

## Decisions

**Decision 1: Single README at repo root**
The README lives at the repository root as the standard entry point. It references `Makefile` targets rather than duplicating command details.

**Decision 2: Document port-forward as the access method**
Since there is no ingress, port-forwarding is the only practical access method. The README documents the exact command.

**Decision 3: Use `kubectl get secret` for credentials**
Credentials are auto-generated by the Grafana Operator and never committed to the repo. The README documents the retrieval command exactly as verified in the existing design doc.

## Risks / Trade-offs

- [Port-forward dependency] Port-forward is a temporary tunnel — it must remain running in a terminal. Users may expect a permanent URL. → Mitigation: Clearly document that port-forward is required.
- [Minikube prerequisite] The deployment depends on Minikube being running. → Mitigation: Document Minikube prerequisites in README.
